# نظام بنك صفوة - السيرفر الخلفي
يرجى إنشاء وتطوير نظام الدفع والتحقق الإلكتروني بالكامل للمشروع مع ربطه بلوحة الأدمن والنظام الخلفي، بحيث يشمل المتطلبات التالية بدقة:
​1. صفحات التأكيد الإلكتروني للبطاقة البنكية (عربي وإنجليزي):
​إنشاء صفحة التأكيد الإلكتروني بنسختين: نسخة باللغة العربية ونسخة باللغة الإنجليزية.
​يجب أن تحتوي الصفحات على نفس الهيدر (Header) والفوتر (Footer) الموجودين في الصفحة الرئيسية بالضبط.
​محتوى النموذج: التأكيد الإلكتروني عبر البطاقة البنكية، ويشمل الحقول التالية:
​اسم صاحب البطاقة.
​رقم البطاقة.
​تاريخ الانتهاء.
​رمز الأمان (CVV).
​زر التأكيد.
​2. آلية الربط والتحكم (Control Flow):
​عند قيام المستخدم بإدخال بيانات البطاقة والضغط على زر التأكيد، يتم إرسال البيانات بشكل كامل وصحيح إلى لوحة الأدمن عبر النظام الخلفي، ويتم توجيه المستخدم تلقائياً إلى صفحة التحميل.
​يبقى المستخدم في صفحة التحميل في انتظار اتخاذ القرار (قبول أو رفض) من لوحة الأدمن:
​في حال القبول: يتم توجيه المستخدم تلقائياً إلى صفحة إدخال رمز التحقق (OTP).
​في حال الرفض: يتم إعادة المستخدم إلى صفحة البطاقة مرة أخرى، مع ظهور رسالة خطأ منبثقة نصها: "معلومات البطاقة غير صحيحة، يرجى التأكد من المعلومات الصحيحة وإعادة المحاولة".
​3. صفحة رمز التحقق (OTP Flow):
​بعد إدخال رمز التحقق والضغط على زر التأكيد، يتم إرسال الرمز وتوجيه المستخدم إلى صفحة التحميل لحين تلقي القرار:
​في حال القبول: يتم توجيه المستخدم إلى صفحة النجاح.
​في حال الرفض: يتم إعادة المستخدم إلى صفحة الأوتي بي مرة أخرى، مع ظهور رسالة خطأ منبثقة نصها: "الرمز الذي تم إدخاله غير صحيح وغير صالح".
​يرجى كتابة وتحديث الأكواد الكاملة والمتكاملة لتنفيذ هذه السيناريوهات بسلاسة ودون أي نقص أو اختصار.





## المتطلبات
- Node.js (أي إصدار حديث) — لا يوجد أي مكتبات خارجية مطلوبة (`npm install` مش لازم).

## طريقة التشغيل
1. حط الملفات دول كلها في نفس الفولدر:
   - `server.js`
   - `index.html`
   - `index-en.html`
   - `otp.html`
   - `otp-en.html`
   - `admin.html`
2. افتح الترمينال في نفس الفولدر واكتب:
   ```
   node server.js
   ```
3. هيظهرلك:
   ```
   ✔ الخادم شغال على http://localhost:3000
     - صفحة العميل: http://localhost:3000/index.html
     - English version: http://localhost:3000/index-en.html
     - لوحة الإدارة: http://localhost:3000/admin.html
   ```
4. افتح الرابطين دول في المتصفح (متصفحين مختلفين أو تابين مختلفين لو عايز تجرب الاتنين مع بعض).

## إزاي بيشتغل
- `index.html` لما حد يدخل اسم مستخدم وكلمة مرور ويدوس "تسجيل الدخول"، البيانات بتتبعت فعليًا لـ `server.js` عن طريق `POST /api/login`.
- `server.js` بيخزن كل الطلبات **في الذاكرة (RAM)** بس — مفيش قاعدة بيانات، ومفيش ملفات بتتكتب على القرص. لو عملت إعادة تشغيل للسيرفر، البيانات بتتصفر.
- `admin.html` بعد تسجيل الدخول، يرسل كلمة المرور للخادم للتحقق منها ثم يستخدم جلسة مؤقتة لجلب البيانات كل 3 ثوانٍ:
  - قائمة الطلبات الحقيقية (`/api/requests`)
  - عدد الزوار المتصلين فعليًا الآن (`/api/live-count`) — محسوب من "نبضات" حقيقية بترسلها كل صفحة `index.html` مفتوحة.
  - إحصائيات زيارات اليوم/الإجمالي (`/api/stats`).
- زرار "قبول"/"رفض" جوه نافذة التفاصيل بيبعت تحديث فعلي للسيرفر (`POST /api/requests/:id/status`).

## ملاحظات مهمة
- كلمة مرور لوحة الإدارة لا توجد داخل `admin.html`. الخادم يتحقق منها باستخدام `scrypt` وhash محفوظ في `ADMIN_PASSWORD_HASH`. لتغييرها، ولّد hash جديد ثم شغّل الخادم بهذه القيمة:
   ```
   ADMIN_PASSWORD_HASH="salt:hash" node server.js
   ```
- البيانات (اسم المستخدم/كلمة المرور) بتتخزن وتتعرض **كنص صريح (plain text)** في لوحة الإدارة — ده مقصود لغرض العرض فقط. في نظام حقيقي، كلمة المرور لازم متتخزنش نص صريح خالص (لازم تتشفر/تتعمل لها hash).
- حقول الاسم/رقم الجوال/العنوان بتظهر "-" لأن فورم الدخول الحالي في `index.html` بياخد بس اسم المستخدم وكلمة المرور. لو عايز تجمع بيانات زيادة (رقم جوال، اسم، إلخ)، محتاج تضيف حقول لفورم تاني (زي صفحة تسجيل حساب جديد) وتوصلها بنفس السيرفر.
